OMYQT

개인과 가족·그룹의 성찰 경험을 제품 흐름으로 설계하면서, 정보보호 경계를 기능보다 먼저 고정하는 Privacy-first AI reflection platform입니다.

프로젝트 한눈에 보기

  • 문제: 개인적 성찰 경험은 제품화할수록 더 강한 정보보호 경계가 필요합니다.
  • 접근: Individual → Family/Group 확장과 AI 기능을 같은 Privacy contract 안에서 설계합니다.
  • 기술: Next.js, Supabase, Postgres, Auth, RLS, Edge Functions 등 데이터 경계를 제품 구조에 포함합니다.
  • 공개 경계: 실제 사용자의 성찰·기도·감정·가족·계정·결제 데이터는 이 페이지와 JERRYBAY Content OS의 source로 사용하지 않습니다.

누구의 어떤 문제를 다루는가

개인적인 성찰 기록을 AI와 연결하는 제품은 편의성만으로 설계하기 어렵습니다. 사용자가 개인 영역에서 기록한 내용이 가족·그룹 기능으로 확장될 때 무엇이 공유될 수 있고 무엇은 개인에게만 남아야 하는지 명확해야 합니다. AI 생성 기능 역시 어떤 컨텍스트를 사용할 수 있는지부터 정해야 합니다.

OMYQT는 이 경계를 나중에 추가하는 보안 기능이 아니라 제품 구조의 일부로 다룹니다. 그래서 공개 프로젝트 설명에서도 기능 수나 성장 지표보다 Privacy-first boundary를 먼저 명시합니다.

Jerry의 역할과 공개 범위

공개 가능한 범위에서는 개인·가족·그룹 흐름, AI generation, Subscription을 포함하는 제품 구조와 정보보호 기준을 설계하는 프로젝트로 설명합니다. 실제 사용자 콘텐츠, 실제 가족관계, 계정 식별자, 결제 정보나 내부 Privacy evidence는 공개하지 않습니다.

설계 접근 — 기능보다 데이터 경계를 먼저

Classify개인·가족·그룹·계정 등 데이터 영역을 구분합니다.
Authorize누가 어떤 범위를 읽고 사용할 수 있는지 정합니다.
GenerateAI가 사용할 수 있는 컨텍스트를 허용 범위 안에서 구성합니다.
Verify교차 사용자·교차 그룹 경계가 깨지지 않는지 검증합니다.

제품의 공개 기술 범주에 Auth, RLS, Edge Functions가 포함되는 이유도 같습니다. UI가 보여주는 내용만이 아니라 데이터 접근 경계를 서버·DB 수준에서도 일관되게 유지해야 하기 때문입니다.

핵심 설계 판단

민감 데이터는 외부 AI 운영 자산이 아니다

실제 개인·가족·성찰 데이터는 외부 Router, HERMES memory, research log나 JERRYBAY 콘텐츠 제작 source로 보내지 않는 기본 경계를 유지합니다.

그룹 기능은 개인 Privacy보다 우선하지 않는다

가족·그룹 확장이 있어도 개인에게만 허용된 정보가 넓은 범위로 노출되지 않도록 별도 권한 경계를 둡니다.

AI 기능과 권한을 분리하지 않는다

AI가 생성할 수 있다는 사실과 그 컨텍스트를 읽을 권한은 별개의 문제이므로 허용된 데이터만 모델 입력으로 구성해야 합니다.

출시보다 Privacy Gate가 먼저다

소스 구현, DB/RLS, Auth, Billing, Production은 각각 별도 Gate로 관리하며 포트폴리오에서 미검증 상태를 완료로 표현하지 않습니다.

공개 Evidence와 비공개 경계

  • OMYQT 공개 홈페이지 ↗ — 공개 서비스 경로.
  • JERRYBAY 프로젝트 레퍼런스에 공개된 제품 범위와 기술 범주.
  • 실제 사용자 content/UUID/token/account/payment/Family data는 이 공개 페이지의 Evidence가 아니며 의도적으로 제외됩니다.

현재 상태

`IN BUILD / PRIVACY-GATED`는 제품이 구축 중이며 Privacy/Product Gate를 통과해야 다음 단계로 이동한다는 의미입니다. 이 페이지는 현재 구현 중인 세부 기능이나 미완료 Gate를 완성된 상용 기능처럼 표현하지 않습니다.

재사용 가능한 원칙

  • 민감한 제품은 “무엇을 만들까”보다 “무엇을 절대 흘리지 않을까”를 먼저 정의합니다.
  • 클라이언트 UI에서 숨기는 것만으로 Privacy boundary를 만들지 않습니다.
  • AI prompt에 들어가는 context도 access-control의 일부로 봅니다.
  • Product·Privacy·DB·Auth·Billing·Production Gate를 구분합니다.
  • Portfolio와 Marketing content에도 실제 사용자 민감 데이터를 사용하지 않습니다.
