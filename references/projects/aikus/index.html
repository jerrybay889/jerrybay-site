프로젝트 한눈에 보기

  • 문제: AI 학습이 실제 업무 도구와 분리되면 적용과 재사용이 끊깁니다.
  • 접근: Learning Lab → Work Studio → Archive를 하나의 사용 흐름으로 설계합니다.
  • 운영: My Page, Auth, 권한, Trial/Subscription을 제품 사용 흐름과 함께 다룹니다.
  • 공개 경계: 실제 고객 성과·사용자 데이터·검증되지 않은 출시 결과는 이 페이지에서 주장하지 않습니다.

누구의 어떤 문제를 다루는가

AI 교육을 받은 사용자가 실제 업무로 돌아왔을 때 다시 빈 화면에서 시작하는 문제를 제품 관점에서 다룹니다. 학습 콘텐츠와 업무 도구가 별도 시스템이면 배운 방법, 입력 맥락, 만들어진 결과와 다음 재사용이 서로 다른 곳에 흩어집니다.

AIKUS는 학습과 작업을 기능 목록으로 분리하기보다 배우고 → 적용하고 → 남기고 → 다시 쓰는 흐름으로 연결하는 것을 목표로 합니다.

Jerry의 역할과 공개 범위

이 프로젝트에서 공개하는 역할은 제품 구조 설계와 구축 방향 수립입니다. 현재 공개 범위는 Learning Lab, Work Studio, Archive, My Page와 Subscription/Payment integration을 포함하는 제품 구조입니다. 세부 구현 상태는 Gate에 따라 바뀔 수 있으므로 이 페이지에서는 특정 기능의 출시 완료를 과장하지 않습니다.

Learning Lab

학습 주제와 실습 맥락을 이해하는 영역.

Work Studio

학습한 방법을 실제 문서·기획·분석 등 업무 결과로 연결하는 영역.

Archive

결과물을 축적하고 이후 작업에서 다시 찾고 재사용하기 위한 구조.

Account / Subscription

사용자별 접근과 지속 사용 조건을 관리하는 제품 운영 범위.

어떻게 구조화했는가

LEARN업무 맥락이 있는 학습과 실습.
WORK실제 업무 Task에서 결과 생성.
ARCHIVE결과와 맥락을 사용자별로 축적.
REUSE이전 결과를 다음 업무의 입력으로 활용.

이 구조의 핵심은 페이지를 많이 만드는 것이 아니라, 한 단계에서 다음 단계로 넘어갈 때 사용자가 맥락을 잃지 않도록 하는 것입니다. 제품 기능과 인증·권한·구독 같은 운영 조건도 같은 사용자 흐름 안에서 검토합니다.

핵심 설계 판단

학습과 실행을 하나의 제품 문제로 본다

교육을 끝낸 뒤 별도 도구로 옮겨가는 대신, 배운 맥락을 실제 업무 결과로 이어가는 흐름을 중심으로 설계합니다.

Archive를 부가 기능으로 보지 않는다

생성된 결과가 사라지지 않고 다음 작업의 입력이 되어야 학습과 실행이 반복 가능한 자산이 됩니다.

Auth와 권한을 UI 뒤의 문제로 미루지 않는다

사용자별 결과 축적과 재사용에는 접근 경계가 필요하므로 제품 계약에 함께 포함합니다.

결제는 출시 완료와 별개로 Gate를 둔다

Payment integration이 제품 범위에 있다고 해서 실제 결제·PG·구독 상태를 검증 없이 완료로 표현하지 않습니다.

현재 상태를 어떻게 읽어야 하나

`IN BUILD / PRODUCTION ITERATION`은 제품이 계속 구축·검증되고 있다는 의미입니다. 특정 Auth, Billing, Release Gate의 세부 완료 여부는 시점에 따라 달라지며, 이 포트폴리오 페이지는 그 세부 개발 상태를 실시간 제품 상태판처럼 과장하지 않습니다. 공개적으로 안전한 제품 방향과 기술 범주를 설명하는 것이 목적입니다.

재사용 가능한 설계 원칙

  • 교육 콘텐츠보다 적용할 업무와 결과물을 먼저 정의합니다.
  • 실행 결과가 다음 Task에서 재사용될 위치를 설계합니다.
  • Auth·권한·구독을 제품 외부의 나중 문제로 미루지 않습니다.
  • 학습 완료보다 실제 Task 흐름이 끝까지 연결되는지를 검증합니다.
  • 구축 중인 기능과 검증 완료된 기능을 공개 문구에서 구분합니다.
