# Content Publishing Contract

## Purpose

`/content/` is the public archive for project pages and future Korean-first articles about AI product design, work transformation, education, and execution. It is a static, indexable surface: the list is readable without JavaScript and each entry has its own HTML route.

## Required source packet for each new article

1. A public-safe source or Owner-approved factual input.
2. Korean title, one primary topic, and a concise answer-first summary.
3. The permitted claim boundary, external references where appropriate, and any rights/attribution note.
4. A target route, description, publication date, and related project or home-section link.

If any item is missing, record `INPUT NOT AVAILABLE` in the work packet and do not publish the entry.

## Static page shape

- `/content/` contains a static card for every published item and supports `?type=project` as a progressive-enhancement filter.
- Every individual page has one Korean-first H1, a description meta tag, one primary contact route, a related-content return link, and only resolved internal assets/links.
- Project pages include product purpose, current status or employer-role context, scope, and verified technology/role categories.

## SEO/GEO quality gate

- Write an answer-first introduction that can stand alone in search or an AI answer surface.
- Use descriptive title, meta description, heading hierarchy, and internal links; do not manufacture keywords, outcomes, testimonials, dates, or customer relationships.
- Validate all public routes, resource policy, role/claim boundaries, desktop/mobile browser behavior, and rendered output before a new batch is committed.

## Publishing cadence and approval

This contract supports frequent publication, but it does not authorize automatic daily generation or release. Every batch requires a source packet and Owner publishing input. Production deployment remains a separate Owner approval.
